# Security contract

The second human review result in docs/SECOND_SECURITY_REVIEW_RESULT.md supersedes the original installation, WordPress deployment and public proxy design. HOLD remains in effect until a separate approval. No privileged component has been installed/executed by the agent; no deployment request is authorized at the third-review checkpoint.

Only HTTP(S), public DNS/IP destinations and default HTTP(S) ports. Reject credentials/fragments, internal/single-label names, private/reserved/mapped IPv6, metadata and the audit host. Resolve every connection, pin verified IPs, revalidate redirects and browser resources. Browser sandbox remains enabled; service workers/downloads are disabled. Validating proxy CONNECT permits public port 443 only. Time/body/inventory/request/concurrency caps remain mandatory.

Browser → WordPress nonce/session REST → WordPress PHP → localhost engine with server-held secret. Engine host binding is 127.0.0.1:3101; the container binding is internal with only host-loopback published. Public nginx exposes only GET /perf-engine/health and refuses other /perf-engine/ paths. Incoming public headers/bodies are not passed to health. No browser-supplied X-Engine-Secret is forwarded. Audit/order/report/admin/quote/SSE remain localhost-only. Private reports require strong tokens hashed at rest plus order/contact/session verification and rate limits. Fixed claims are not verification.

Root trust transition: reviewed Git blobs → deterministic archive → DATA copied into protected root staging → human-approved SHA-256 checked on the root-owned copy → bounded safe regular-file extraction → root-owned reviewed installer. No executable/module from the codexperf repository ever runs as root. The bootstrap is human-supplied trusted stdin using installed system tools/stdlib only; it does not source/read code for execution from the repository. Privileged installer inputs never switch back to the workspace. All root staging/installed ancestors are checked for symlinks, ownership and write permissions, and complete extracted file hashes are revalidated against root-owned approval metadata.

Installer preflight checks immutable archive/snapshot identity, Docker daemon health/systemd cgroup driver, required systemd version/manager, x86_64, fixed paths, secure root-only runtime settings and no stale request, including dangling links. It fails before installing/enabling on initial failure and repeats before enabling. The request is a fixed non-executable action/commit schema, atomically renamed to a unique claimed name before validation/long work; claimed data is bounded/owned/no-follow. Cleanup never deletes a newer request. The commit is a request label, not source attestation; source digest records actual snapshot bytes.

Automatic watcher has no Plesk/WordPress write path, no PHP execution and no plugin installation. Its service writes only runtime state and the workspace .ops directory. Separate human-approved PHP artifact deployment is tied to an exact reviewed commit/archive/plugin hash. Its reviewed helper reads approved payload, clears supplementary groups and drops to the verified DEV PHP UID/GID before all WordPress writes. Generated config.php is 0600 owned by that UID, with no shared-group read. Actual FPM ownership/readability must be verified by the human. Shared Plesk authority is the reason automation is disabled.

Both official base images are pinned by registry-verified SHA-256 index digests; BASE_IMAGE_DIGESTS.json records tags, index and linux/amd64 digests and verification provenance. The app network must have the exact name, bridge/local driver/scope, Internal=true, role label and persisted network ID. Create failure, malformed inspection or identity/configuration mismatch aborts; runtime start validates before any containers are started. Only the validating proxy receives an external network. Non-root UID10001, cap-drop ALL, no-new-privileges, official seccomp, no host-root/Plesk/socket mounts, read-only runtime/source, bounded tmpfs/logs/PIDs, 4 CPU/1700 MiB aggregate ceiling and browser concurrency one remain required. Runtime rollback and three-release retention, including failed attempts, remain in place.

Local tests/mocks are not security approval or deployed evidence. Actual Docker/kernel sandbox, effective limits, egress isolation, root installation, public health and WordPress/WooCommerce controlled E2E remain release gates. Production and unrelated domains remain untouched.
